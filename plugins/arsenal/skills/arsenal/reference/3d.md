# 3D scenes and objects

Building blocks for real-time 3D on the web with Three.js and React Three Fiber (R3F): floating/rotating hero objects, scroll-linked cameras, particle fields, loaded GLB models, and premium-looking lighting — the vocabulary behind sites like getlayers.ai and high-end agency/SaaS landing pages.

**When NOT to use this.** Skip 3D when: the audience is mobile-heavy and battery/thermal budget matters (a WebGL canvas easily costs more than the rest of the page combined); the interface is content-dense product UI where a floating object would be pure decoration competing with real tasks; the team can't own the dependency weight (`three` + `@react-three/fiber` + `@react-three/drei` is commonly 150–300KB gzipped before a single model or texture loads); or there's no design intent behind it — a rotating abstract blob bolted onto a hero section reads as template filler, not craft. If in doubt, a well-executed CSS/SVG effect (see other arsenal references) often reads as more intentional than a generic 3D scene.

## 1. Floating/rotating hero object

**What/why** — A single object (not a stock sphere) that idles with organic float + rotation via drei's `Float`. The default "hero 3D thing" pattern; do it with restraint and it reads as premium, do it with a default torus-knot and it reads as a template.

**License** — all three MIT, confirmed via npm and GitHub on 2026-09-09. Versions as of that date: `three` 0.186.0, `@react-three/fiber` 9.7.0, `@react-three/drei` 10.7.8. `three` publishes a new minor roughly monthly, so treat the number as a datestamp, not as a pin: check npm before writing it into a project's package.json. The license is the durable fact here, the version is not.

```bash
npm install three @react-three/fiber @react-three/drei
```

```jsx
import { Canvas } from '@react-three/fiber'
import { Float, Environment } from '@react-three/drei'

export default function Hero3D() {
  return (
    <Canvas camera={{ position: [0, 0, 5], fov: 40 }} dpr={[1, 2]}>
      <ambientLight intensity={0.4} />
      <directionalLight position={[3, 3, 3]} intensity={1.2} />
      <Float speed={1.5} rotationIntensity={0.6} floatIntensity={0.8}>
        <mesh>
          <icosahedronGeometry args={[1, 1]} />
          <meshPhysicalMaterial
            color="#2b2f77"
            roughness={0.15}
            metalness={0.1}
            clearcoat={1}
            transmission={0.15}
          />
        </mesh>
      </Float>
      <Environment preset="city" />
    </Canvas>
  )
}
```

**Avoid the generic-Spline-blob look** — swap `meshStandardMaterial` defaults for a `meshPhysicalMaterial` tuned to brand colors (not stock purple/blue gradients), pick a geometry tied to the product (a folded card, a stylized icon extrusion, a low-poly version of a real object) instead of `TorusKnotGeometry` or `SphereGeometry`, and use exactly one hero object — a cluster of five floating shapes is the single biggest tell of a template.

## 2. Scroll-linked object/camera

**What/why** — Drive rotation, position, or camera movement from scroll progress so the 3D piece feels choreographed to the page rather than just idling. Pair with a scroll library (see the motion reference) or a plain scroll listener.

**License** — same packages as above (MIT).

```jsx
import { useRef, useState, useEffect } from 'react'
import { Canvas, useFrame } from '@react-three/fiber'

function ScrollObject({ progress }) {
  const ref = useRef()
  useFrame(() => {
    if (!ref.current) return
    ref.current.rotation.y = progress.current * Math.PI * 2
    ref.current.position.y = -progress.current * 2
  })
  return (
    <mesh ref={ref}>
      <torusGeometry args={[1, 0.35, 32, 100]} />
      <meshStandardMaterial color="#e8542a" roughness={0.3} />
    </mesh>
  )
}

export default function ScrollScene() {
  const progress = useRef(0)
  useEffect(() => {
    const onScroll = () => {
      const max = document.body.scrollHeight - window.innerHeight
      progress.current = max > 0 ? window.scrollY / max : 0
    }
    window.addEventListener('scroll', onScroll, { passive: true })
    return () => window.removeEventListener('scroll', onScroll)
  }, [])
  return (
    <Canvas dpr={[1, 2]} camera={{ position: [0, 0, 5] }}>
      <ambientLight intensity={0.5} />
      <directionalLight position={[2, 2, 2]} />
      <ScrollObject progress={progress} />
    </Canvas>
  )
}
```

**Avoid the generic look** — drive something structural (an object assembling itself, a camera move that reveals product detail) rather than a plain 360° spin; a spin-only scroll rig is the 3D equivalent of a fade-in-on-scroll — expected, forgettable.

## 3. Particle field

**What/why** — A lightweight `Points` field for ambient depth behind text/hero content. Cheap relative to meshes since it's one draw call.

**License** — `three` MIT (as above), no extra package needed beyond `@react-three/fiber`.

```jsx
import { useMemo, useRef } from 'react'
import { Canvas, useFrame } from '@react-three/fiber'
import * as THREE from 'three'

function Particles({ count = 800 }) {
  const ref = useRef()
  const positions = useMemo(() => {
    const arr = new Float32Array(count * 3)
    for (let i = 0; i < count; i++) {
      arr[i * 3] = (Math.random() - 0.5) * 8
      arr[i * 3 + 1] = (Math.random() - 0.5) * 8
      arr[i * 3 + 2] = (Math.random() - 0.5) * 8
    }
    return arr
  }, [count])

  useFrame((_, delta) => {
    if (ref.current) ref.current.rotation.y += delta * 0.03
  })

  return (
    <points ref={ref}>
      <bufferGeometry>
        <bufferAttribute attach="attributes-position" args={[positions, 3]} />
      </bufferGeometry>
      <pointsMaterial size={0.03} color="#9aa0ff" sizeAttenuation transparent opacity={0.7} />
    </points>
  )
}

export default function ParticleScene() {
  return (
    <Canvas dpr={[1, 1.5]} camera={{ position: [0, 0, 5] }}>
      <Particles />
    </Canvas>
  )
}
```

**Avoid the generic look** — keep the count low (hundreds, not tens of thousands) and tie color to brand palette, not default white/purple; particles as a subtle texture read as intentional, particles as the whole hero read as a screensaver.

## 4. Loading a free .glb model

**What/why** — drei's `useGLTF` loads and caches a `.glb`/`.gltf` model with Suspense support. Use a real object relevant to the product instead of an abstract shape when you have one.

**License** — `@react-three/drei` MIT (as above). Model licenses are separate and per-asset — verify before using any downloaded model (see Live lookup).

```jsx
import { Suspense } from 'react'
import { Canvas } from '@react-three/fiber'
import { useGLTF, Environment, ContactShadows } from '@react-three/drei'

function Model(props) {
  const { scene } = useGLTF('/models/product.glb')
  return <primitive object={scene} {...props} />
}
useGLTF.preload('/models/product.glb')

export default function ModelViewer() {
  return (
    <Canvas dpr={[1, 2]} camera={{ position: [0, 1, 4], fov: 35 }}>
      <ambientLight intensity={0.6} />
      <Suspense fallback={null}>
        <Model scale={1.2} />
        <Environment preset="studio" />
        <ContactShadows opacity={0.4} blur={2.5} far={2} />
      </Suspense>
    </Canvas>
  )
}
```

**Avoid the generic look** — a real, specific object (an actual product, a custom-modeled icon) beats a stock "abstract 3D shape pack" download every time; if using a downloaded model, re-tint materials to brand colors rather than leaving the source's default palette.

## 5. Premium lighting/environment in one line

**What/why** — drei's `Environment` component applies image-based lighting (IBL) from an HDRI preset, which is most of what makes a scene look "expensive" versus flat-lit default Three.js materials.

**License** — `@react-three/drei` MIT. Built-in presets (`"city"`, `"studio"`, `"sunset"`, `"warehouse"`, etc.) are bundled/fetched by drei from its own CDN — no separate asset license concern for those presets.

```jsx
import { Environment } from '@react-three/drei'

// inside a <Canvas>:
<Environment preset="sunset" background blur={0.6} />
```

**Avoid the generic look** — presets are a starting point, not the final answer: dial `blur`, swap to a custom low-res HDRI from Poly Haven tinted toward brand hue, or set `background={false}` and keep your own page background so the environment only lights, doesn't dominate.

## No-code alternative: Spline

[Spline](https://spline.design) is a browser-based 3D design tool (think Figma for 3D) that exports scenes for web embedding without writing Three.js by hand.

- **Free tier**: still exists as of Sep 2026 — unlimited viewers, limited file count, Spline templates; free-tier web exports carry a watermark, removed on paid plans (Starter ~$12–15/mo).
- **Embed package**: `@splinetool/react-spline`, MIT licensed, current major v4.x. Also `@splinetool/runtime` for a framework-agnostic embed.

```bash
npm install @splinetool/react-spline
```

```jsx
import Spline from '@splinetool/react-spline'

export default function SplineScene() {
  return <Spline scene="https://prod.spline.design/your-scene-id/scene.splinecode" />
}
```

**When Spline is the right call** — a non-engineer (designer, founder) needs to iterate on a 3D scene independently and ship fast; the scene is mostly self-contained decoration, not deeply wired into app state.

**When hand-written R3F is better** — you need full control over performance (Spline's runtime is a black box you can't tree-shake or profile line by line), no iframe/extra-runtime weight on top of `three` itself, tight integration with React state/scroll/app logic, or a look that doesn't read as "made in Spline" (the Spline aesthetic is itself becoming a template look — see the opening warning).

## Performance basics

3D-specific must-dos: dispose geometries/materials/textures on unmount, cap `dpr` (e.g. `dpr={[1, 2]}` on `<Canvas>`, never uncapped device pixel ratio), and lazy-mount the `<Canvas>` (dynamic import / mount on viewport-enter) so it isn't in the critical render path. Full budget, LCP/CLS numbers, and the general performance checklist live in `performance.md` — apply that in full before shipping any scene from this file.

## Lehren aus Paulis Churros (2026-09-26)

- **GLB aus Blender ohne Texturen:** Prozedurale Blender-Materialien (Holz, Schindeln) überleben den glTF-Export nicht, übrig bleibt die Grundfarbe. Ohne neuen Bake hilft Weltkoordinaten-Projektion (triplanar) per `onBeforeCompile`, zugeordnet über Materialnamen: CC0-Sätze (Poly Haven, ambientCG) mit Farbe, Normal (OpenGL) und Rauheit, Farbe als `Grundfarbe * Textur / Mittelfarbe der Textur`, damit der Farbton des Modells bleibt. Im Fragment-Shader steht `normal` bei `map_fragment` noch nicht bereit: die Weltnormale aus `vNormal` und `gl_FrontFacing` bilden.
- **Lichtfarbe nie über den Farbton überblenden:** `setHSL(mix(orange, blau))` läuft durch Grün, die Mitte der Dämmerung bekommt einen kranken Grünstich. Immer `Color.lerp` zwischen zwei fertigen Farben.
- **Lichthöfe als additive Points:** mit `premultipliedAlpha: true` und Ausgabe-Alpha 0, sonst schreiben ausgeschaltete Höfe schwarze Quadrate in eine transparente Leinwand. Keine Höfe für Birnen, die in Blickrichtung hintereinander liegen (Seitentraufe), sonst addieren sie sich zu einem Fleck.
- **Birnen einzeln einschalten:** zusammenhängende Teilnetze per Union-Find über den Index finden, je Birne ein Vertex-Attribut `aOrdnung`; die Reihenfolge nach Rang statt nach Abstand vergeben, sonst frisst eine lange Außenkette die Zeit.
